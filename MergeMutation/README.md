# Merge Mutation 2.0

Прототип для **Godot 4.7.2**: десять независимых видов, по пять стадий эволюции. Без внешних зависимостей, рекламы и покупок.

## Модульный ремонт вольера — PR №18

Горизонтальный формат принят после плейтеста PR №17. Ветка `feature/modular-habitat-renovation`: Рогач начинает в бедной камере, десять предметов/покрытий развиваются независимо, у каждого три оформления. Включите **РЕМОНТ**, нажмите маркер, посмотрите варианты и подтвердите установку. Первоначально доступны три отдельные тестовые единицы улучшения; смена установленного оформления бесплатна. Меню **ТЕСТ** начисляет ещё по одному очку и предлагает подтверждаемый сброс только демо-ремонта.

Состояние ремонта сохраняется отдельно от основного профиля v2. В обычном режиме доступны касания предметов, панорама и поиск Рогача. Глобальных стадий в обычном интерфейсе больше нет.

## Живой вольер — PR №16

Ветка `feature/living-habitats`: увеличенные комнаты и отдельная сцена Рогача с областью среды 340×420. Четыре тестовые стадии меняют обстановку от пустой камеры до каменного биома. ## Tactical Mutation Prototype — эксперимент

Ветка `feature/undo-and-corridor-movement`: кнопка **ЭКСПЕРИМЕНТ** в лаборатории открывает десять независимых испытаний с вертикальной прокруткой. Рогач разрушает камни, Слизик проходит кислоту, Крылатик прыгает через один разрыв. Цель — объединить и доставить формы II на отмеченные клетки. Сохранения, десять уровней кампании и её награды не меняются; прогресс эксперимента существует только до его закрытия.

Две бесплатные отмены на попытку восстанавливают последнее успешное действие, включая создание и весь длинный маршрут. Бирюзовые дальние клетки с цифрой — свободные прямые пути: каждый шаг стоит один ход. Камни, разрывы и занятые клетки не пересекаются, слияния не выполняются автоматически.

## Тактическая кампания — PR №10

В кампании перенос и слияние разрешены только между соседями по стороне. Голубые рамки отмечают фиксированные точки появления; занятую выбранную точку нужно освободить. Все десять раскладок переработаны и проверены BFS без бустеров. Тестовый Телепортатор переносит в свободную клетку за заряд, без слияния и списания хода. Песочница сохраняет прежние правила.

## Запуск и управление

1. Импортируйте `MergeMutation/project.godot` в Godot 4.7.2.
2. Нажмите F5. F6 также запускает открытую `scenes/main.tscn`.
3. Кнопка **ВИД** справа от монет открывает выбор одного из десяти видов. **СОЗДАТЬ** добавляет первую стадию выбранного вида за 10 монет.
4. В песочнице перетаскивайте существ в любые пустые клетки либо объединяйте **одинаковые виды одной стадии**. Получается тот же вид следующей стадии. Максимум текущего каталога — V.
5. Награда за объединение: `15 × новая стадия` монет. Полное поле и недостаток денег не списывают монеты.
6. **КОЛЛЕКЦИЯ** показывает пять стадий выбранного вида. Первое получение формы открывает её навсегда, просмотр формы ничего не открывает.
7. **НАСТРОЙКИ**: звук и подтверждаемая новая игра. Кнопка порталов расположена между коллекцией и настройками.

Мышь и основной палец поддерживаются; дополнительные касания игнорируются. Потеря фокуса отменяет перетаскивание. Поле 5×6 сохраняет прежнюю геометрию и определяет цель по клетке, даже когда большой силуэт перекрывает соседнюю.

## Сохранения

Новый файл: `user://merge_mutation_save_v2.json`, схема 2. При первом запуске без него старый `merge_mutation_save.json` автоматически переносится в **отдельный** файл. Старый файл остаётся неизменным. Числовые уровни 1–10 становятся стадией I соответствующего вида; старый `highest` открывает только базовые формы. Монеты, слияния и дополнительные поля сохраняются.

Настройка звука по-прежнему хранится отдельно в `user://merge_mutation_settings.cfg`.

Повреждённые данные блокируют запись, игра показывает временное начальное поле. Исправьте файл и перезапустите игру либо подтвердите новую игру. Перед заменой существующего проблемного/старого файла v2 создаётся копия `.pre-update-<hash>.bak`. Запись выполняется через временный файл. Подробнее: [безопасность миграции](docs/species-evolution.md).

## Проверки и рабочие артефакты

Git-корень и Godot-проект — разные каталоги с одинаковым именем: исходники находятся во
**внутреннем** `MergeMutation/`. Запускайте инструменты ниже из этой папки либо вызывайте
их по полному пути из любой рабочей директории. Они сами определяют проект, задают
`--path` и рабочий каталог процесса; не используйте внешний корень как Godot-проект.

```powershell
$godot = 'C:/path/to/godot.exe'
./tools/check_workspace.ps1 -GodotPath $godot
./tools/run_godot.ps1 -GodotPath $godot -Mode import -Label pr20-import
./tools/run_godot.ps1 -GodotPath $godot -Mode import -Label pr20-reimport
./tools/check_gdscript.ps1 -GodotPath $godot -Label pr20-compile
./tools/check_landscape.ps1 -GodotPath $godot -IncludePortraitRegression -Label pr20
./tools/check_landscape.ps1 -GodotPath $godot -Gpu -IncludePortraitRegression -Label pr20
./tools/run_godot.ps1 -GodotPath $godot -Mode runtime -Label pr20-smoke
```

Состав регрессий и логика тестов сохранены: 29 headless-наборов, 11 GPU-наборов,
124 GDScript. Инструменты проверяют код завершения и строки SCRIPT ERROR/ERROR/WARNING/FAIL.
Каждый запуск создаёт собственный каталог с UTC-датой, типом, меткой и коротким ID
в корневом `logs/import/`, `logs/runtime/` или `logs/tests/`.
APPDATA изолирован во внутренней `.godot/test-appdata/` и восстанавливается после команды.
Обычный запуск через редактор продолжает использовать пользовательский профиль.

Отдельный тест и новые снимки PR20:

```powershell
./tools/run_godot.ps1 -GodotPath $godot -Mode script -Script res://tests/world_progression_ui_test.gd -Gpu -Label pr20-capture
```

Снимки/одноразовые тестовые профили и доказательства решений остаются во внутренней
игнорируемой `.godot/`: пути `res://.godot/...` не менялись. После проверки нужные материалы
можно явно добавить в `docs/`; существующие отчёты и их ссылки не перемещались.
Команды в старых отчётах отражают предыдущие этапы; для текущих запусков используйте
эти обёртки. Политика артефактов и аудит: [workspace-cleanup.md](docs/workspace-cleanup.md).

Экспорт разрешён только в корневой `builds/android/` или `builds/windows/`.
После отдельной настройки существующего export preset:

```powershell
./tools/run_godot.ps1 -GodotPath $godot -Mode export -Platform android -ExportPreset Android -Label android-release
```

Имя сборки по умолчанию содержит UTC-дату; существующий файл не перезаписывается.
В текущем проекте export_presets.cfg отсутствует, поэтому уборка не создаёт APK/AAB
и не меняет настройки Android. Пароли/ключи подписи, локальные логи и сборки не добавляются
в Git. `*.png.import`, `*.gd.uid`, игровые JSON/TXT/PNG и утверждённые docs сохраняются.
## Файлы и расширение

- `scripts/mutant_catalog.gd`: стабильные ID, параметры видов, максимумы стадий, правила объединения.
- `scripts/save_codec.gd`: чистое преобразование старых/новых данных, без файловых операций.
- `scripts/main.gd`: поле, экономика, управление, открытия и безопасная запись.
- `scripts/lab_view.gd`: лаборатория, выбор вида, коллекция и анимации интерфейса.
- `scripts/mutant_art.gd`, `mutant_sizes.gd`, `species_tint.gdshader`: изображения, временные стадии, размеры и выборочная палитра.
- `scripts/lab_audio.gd`, `merge_burst.gd`: прежние звуки и частицы, без изменения.
- `assets/mutants/README.md`: подключение будущих PNG по стадиям; исходные шесть PNG сохранены.

Стадии II–V — временные варианты, а не финальные художественные ассеты. Четыре последних вида сохраняют процедурные рисунки. Каталог допускает добавление видов и стадий без изменения правил поля. Кампания с десятью уровнями добавлена отдельными компонентами; сложные препятствия, жилища, реклама и покупки пока отсутствуют.
