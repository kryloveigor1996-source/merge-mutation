# Независимые виды и эволюции — технический отчёт

## Модель

В клетке хранится `null` либо объект, например:

```json
{"species_id":"slime","evolution_stage":3}
```

ID стабилен и не зависит от названия или PNG. `mutant_catalog.gd` содержит десять видов:

| ID | Название | Цвет | Максимум |
|---|---|---|---|
| slime | Слизик | #A3DE37 | V |
| eyeball | Глазастик | #E66DB8 | V |
| horn | Рогач | #F18A35 | V |
| bubble | Пузырник | #F47785 | V |
| shell | Панцирник | #48B9E4 | V |
| wing | Крылатик | #7654C8 | V |
| tentacle | Щупальник | #28B6A7 | V |
| chimera | Химера | #E3B449 | V |
| rex | Мутант-рекс | #C64C43 | V |
| ultra | Ультрамутант | #47516C | V |

Запись каталога: `id`, `name`, `color`, `max_stage`, `images` (номер стадии → путь), `display` (`art_index`, `size_index`, `stage_growth`), `available`.

`Catalog.can_merge(a,b)` проверяет известность обеих форм, одинаковые ID и стадии, максимум конкретного вида. `Catalog.evolve(form)` возвращает копию следующей формы либо исходную копию, если эволюция невозможна. Ни поле, ни правило слияния не содержат ограничения «10 видов» или «5 стадий».

Добавить вид можно через запись каталога или `register_species()`. Тест регистрирует одиннадцатый вид с семью стадиями, проверяет слияние VI→VII, максимум и запасную отрисовку без PNG. `LEGACY_IDS` нельзя переупорядочивать: это историческое соответствие числовых уровней.

Все десять видов доступны в тестовом режиме. Выбор вида не тратит монеты и не открывает форму; создание стадии I стоит прежние 10 монет. Формула награды прежняя, её аргумент теперь стадия: `15 × новая стадия`. Например, Крылатик I + I → II даёт 30 монет. Это больше не переход между разными видами.

## Отрисовка

Шесть исходных PNG не изменены ни по байтам, ни по настройкам импорта. Они являются базами slime/eyeball/horn/bubble/shell/wing. Остальные четыре вида сохраняют прежние процедурные силуэты. Для будущего отдельного изображения стадии задайте `images[stage]`; при его отсутствии используется база, затем процедурный рисунок. Неизвестный вид сохраняет данные, отображается нейтрально и не объединяется.

Стадии II–V используют небольшое увеличение (4% за стадию, общий предел 86 design-px), ограниченную цветовую коррекцию насыщенных фиолетовых участков и 1–5 маркеров стадии. У IV–V есть золотая дуга; максимум получает золотые маркеры и верхний акцент. Это временные варианты, а не 50 финальных иллюстраций. В коллекции максимальная видимая сторона всегда 48 px.

Shader выборочно сдвигает фиолетовую шерсть Глазастика к малиново-розовой, Крылатика к индиго; нейтральные блики, тёмный контур, зелёные глаза, оранжевые крылья и альфа сохраняются. GPU-контактный лист позволяет проверить все стадии. Исходники не перекрашены.

Размер определяется видимым альфа-силуэтом. Прежние Tween/AnimationPlayer, mipmaps, фильтрация, безопасные рамки перетаскивания и z-порядок сохранены. Большие формы могут немного перекрывать соседей; попадание рассчитывается по неизменной сетке 62 px, а не по рисунку. Проверены прежние 62/64px бюджеты, все стадии в рамке поля, карточки всех 50 форм и граничные перетаскивания.

## Схема и миграция

Схема 2 содержит `schema_version`, `cells`, `coins`, `merges`, `active_species`, `discoveries`. Открытия — уникальные ключи `species_id:stage`, например `wing:3`. Независимые дополнительные поля корня и объектов существ копируются. Настройки звука остаются в отдельном прежнем CFG, код их миграции не менялся.

Алгоритм запуска:

1. Если существует `user://merge_mutation_save_v2.json`, загрузить его. Иначе искать прежний `merge_mutation_save.json`.
2. Проверить весь документ до применения состояния. Монеты/слияния должны быть целыми неотрицательными числами; ID и стадия валидируются.
3. Старые числа 1–10 → соответствующие виды стадии I, 0/null → пустая клетка. `highest` вместе с максимальным существом открывает только базовые формы до этого вида; ни одна стадия II–V не выдумывается. Для аудита сохраняется `legacy_highest`.
4. Отсутствующие поля получают безопасные значения (монеты 100, слияния 0, пустое поле). Короткое поле дополняется null; лишние клетки сохраняются в `retained_overflow_cells`. Это сохраняет данные, но не добавляет клетки на экран.
5. Известная либо неизвестная корректная форма сохраняется вместе с дополнительными полями. Неизвестный активный вид заменяется на slime для создания, исходное значение сохраняется в `retained_active_species`. Известные стадии выше текущего каталога сохраняются, но не объединяются.
6. Новый файл записывается отдельно через `.tmp` и переименование. Старый файл не меняется. При необходимости нормализовать/заменить существующий файл создаётся побайтовая `.pre-update-<SHA256 prefix>.bak`.

Неподдерживаемая версия, некорректный JSON, повреждённая форма или неверные типы блокируют запись. Игра показывает временное начальное поле и сообщение. Приобретение/движение в этом временном сеансе не перезапишет повреждённый файл. Исправление файла и перезапуск либо явно подтверждённая новая игра снимают блокировку; новая игра сначала резервирует существующий v2. Старый legacy-файл остаётся нетронутым и при сбросе.

Повторный запуск использует v2 и не переносит legacy повторно. JSON-числа в дополнительных неизвестных полях могут нормализоваться `1` → `1.0` средствами Godot; числовое значение сохраняется. Проверяется семантическая стабильность после JSON round-trip.

На этой машине основная сцена реально создала v2 из пользовательского старого файла: SHA256 старого файла не изменился, монеты и слияния совпали. Приватные сохранения не добавлены в репозиторий. Кастомные пути тестов никогда не используют пользовательский legacy-файл.

## Обновление и ручная приёмка

PR не объединяется автоматически. Для просмотра до merge в GitHub Desktop: Fetch origin → Current branch → feature/mutant-species-evolution. После одобрения/merge: main → Fetch origin → Pull origin. Не удаляйте папку старого проекта и пользовательские сохранения. Откройте именно `MergeMutation/project.godot` этой рабочей копии, дождитесь импорта; если Godot предлагает Reload, примите его, затем F5.

Проверьте монеты и поле после миграции; выберите Слизика, Глазастика и Крылатика; создайте пары и объедините до II. Разные виды/стадии объединяться не должны. Максимум V проверен автоматически; вручную его удобнее осматривать на контактном листе, не редактируя рабочий файл сохранения. Проверьте коллекцию, повторный запуск, звук, быстрые касания/перетаскивания, читаемость маркеров на телефоне и безопасные области экрана Android. Убедитесь, что временные стадии достаточно различимы для дальнейшей художественной доработки.
