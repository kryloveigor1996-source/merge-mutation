# Подземный комплекс — PR №15

Основа: актуальный `main`, PR №14 объединён (`1aff5b4`), статус проверен через GitHub. Ветка `feature/underground-laboratory`. Это дополнительный демонстрационный экран; игрок не строит комнаты и не развивает существ. Вход — **КОМПЛЕКС** в верхней панели песочницы. Нижняя навигация, создание и поле сохранены; в основной кампании вход скрыт.

## Четыре демонстрационных этажа

| ID | Глубина | Высота | Комнаты |
|---|---:|---:|---|
| `floor_surface` | 0 | 200 | Декоративное главное здание, оборудование и вход; камер нет |
| `floor_01` | −1 | 240 | Каменный вольер Рогача, кислотный отсек, воздушный отсек |
| `floor_02` | −2 | 300 | Минеральная камера 130×232 и зелёная камера 170×244 |
| `floor_03` | −3 | 440 | Усиленная секретная камера 308×372 без назначенного вида |

Этажи составляют единое пространство высотой **1180** логических единиц. Три малые комнаты имеют размер **98×174**, разные палитры и рамки, а также выделенную область будущих объектов. Левый край занимает шахта лифта с рельсами/кабелем, между секциями — перекрытия и трубы. Секретная камера содержит защитные панели, предупреждение и абстрактную тень оборудования; неизвестный редкий вид не раскрывается.

Все четыре этажа доступны для просмотра. Только `habitat_horn` открывает информационную панель: существующий PNG Рогача, название из каталога, этаж, ID, описание и явно демонстрационный статус. Остальные пять комнат показывают «Камера пока недоступна» и не загружают спрайты закрытых видов. Доступность в конфигурации **не связана с настоящими открытиями профиля**.

## Архитектура и изменённые файлы

- `data/complex/floors.json`: стабильные ID, глубина, название, переменная высота, тема, доступность просмотра и ссылки на комнаты.
- `data/complex/habitats.json`: независимые ID помещений, ссылка на этаж, необязательный существующий `species_id`, класс размера, тема, имя, описание, геометрия и демо-доступность.
- `scripts/complex_registry.gd`: загрузка/валидация, вычисление верхних координат и мировых прямоугольников, поиск по ID/виду и отбор видимых секций.
- `scripts/underground_complex.gd`: экран, прокрутка, инерция, навигация, лифт, информационная панель и безопасные публичные переходы.
- `scripts/complex_floor.gd`: фон этажа, поверхность, шахта, освещение и создание только его комнат.
- `scripts/habitat_view.gd`: процедурная оболочка/биом, существующая графика вида только для доступного демо, область будущих объектов и короткая подсветка.
- `scripts/lab_view.gd`: кнопка входа 114×44, заголовок лаборатории и закрытие комплекса при существующей навигации. Нижние кнопки не удалены и не уменьшены.
- `tests/complex_test.gd`, `tests/complex_ui_test.gd`, `tests/fixtures/complex_50.json`: модель, отрицательные конфигурации, взаимодействия и стресс-проверка.
- README, этот документ, [отдельный ручной плейтест](underground-complex-playtest.md), снимки `docs/complex-*.png`, Godot `.uid`/`.import` новых файлов.

Модели кампании, тактические испытания, отмена/длинные команды, экономика, SaveCodec и каталог видов не изменены. Комплекс получает ссылку на игру только для интеграции экрана; сам не вызывает сохранения, выдачу наград или открытие форм.

## Контракт конфигурации

Файлы имеют корневые объекты `{"floors": [...]}` и `{"habitats": [...]}`. Минимальный пример добавления секции и технического помещения:

```json
{
  "floor_id": "floor_04",
  "depth": 4,
  "name": "Технический резерв",
  "height": 320,
  "theme_id": "industrial",
  "preview_accessible": true,
  "habitats": ["habitat_service"]
}
```

```json
{
  "habitat_id": "habitat_service",
  "floor_id": "floor_04",
  "size_class": "medium",
  "theme_id": "crystal",
  "name": "Техническая камера",
  "description": "Демонстрационный резерв без наград.",
  "preview_accessible": false,
  "rect": [32, 48, 308, 250],
  "interaction_rect": [8, 40, 292, 180]
}
```

Добавить первый объект в массив этажей, второй — в массив комнат; перезапустить проект и выполнить тесты. Для существующего вида добавить его ID из `mutant_catalog.gd` в `species_id`. Отсутствие поля означает техническое/неназначенное помещение, а не новый вид. Не нужно переименовывать вид при переносе комнаты.

`rect` — `[x, y, width, height]` относительно верхней границы **своего этажа**. Этажи сортируются по `depth`, верхние координаты вычисляются накоплением высот. Зарезервированы шахта слева (x < 28), правый край после x=348 и верхние 36 единиц заголовка. Минимальная ширина/высота комнаты — 44, высота секции — 120–4000. Геометрия должна быть конечной и положительной, нижний край не может выходить за весь комплекс.

Высота комнаты может превосходить высоту её секции и занимать несколько этажей. Якорь остаётся на первом этаже; нижележащие комнаты необходимо расположить вне её мирового прямоугольника. Валидация проверяет пересечения **глобально**, а рендер держит якорную секцию активной, пока видна высокая комната. Комнаты рисуются поверх фоновых секций, чтобы следующий этаж не перекрывал такую камеру. Это автоматически проверено отдельным межэтажным примером.

Валидация также проверяет уникальность ID и глубин, ссылки в обе стороны, принадлежность комнаты этажу, размеры/границы, bool-доступность, существование видов в общем каталоге и границы локальной `interaction_rect`. При ошибке модель очищается целиком, экран показывает сообщение и кнопку возврата. Неизвестная корректная тема использует нейтральную временную палитру; новые художественные темы потребуют расширения рендера. Схема размеров позволяет менять комнаты без смены их ID.

## Прокрутка и навигация

Стандартный `ScrollContainer` отвечает за область просмотра и отсечение; экран обрабатывает mouse/touch жесты, поскольку проект отключает эмуляцию мыши. Во время drag положение следует пальцу, после отпускания применяется короткая ограниченная инерция. Колесо плавно двигает накопленную цель, включая быстрые повторные события. Верхняя/нижняя границы ограничены. Пройденный путь жеста и смещение отличают прокрутку от нажатия, в том числе при жесте туда-обратно; отменённое touch-событие не открывает комнату.

Нижняя панель закреплена: **Наверх**, **Вниз**, **Лифт**, **Назад**. Индикатор показывает этаж у верхнего края области просмотра. Небольшая подложка грунта после последнего этажа позволяет выровнять его начало с верхним краем, даже если он ниже высоты viewport. Переходы рядом занимают 0,24 секунды; дистанция более шести viewport перемещается сразу, без долгого пролёта. Новый жест отменяет прежнюю анимацию.

Лифт показывает номер, имя, число конфигурационных комнат, доступность просмотра и стрелку текущей секции. На поверхности камер 0: главное здание — декорация, не вольер. Список лифта тоже прокручивается; выбор строки не срабатывает от свайпа. «Назад» в панели лифта/закрытие карточки возвращают в комплекс; основной «Назад» и Esc выходят в лабораторию. Аппаратная кнопка Back на Android отдельно не проверена.

## Программный интерфейс будущего бестиария

```gdscript
var room = complex.registry.get_habitat_for_species("horn")
var floor = complex.registry.get_floor_for_habitat("habitat_horn")
complex.navigate_to_floor("floor_01")
complex.navigate_to_habitat("habitat_horn") # переход и временная подсветка
complex.highlight_habitat("habitat_horn") # для уже видимой доступной комнаты
```

Геттеры возвращают независимые копии или `{}`. При нескольких помещениях вида выбирается первое по глубине и порядку списка комнаты. Неизвестные/недоступные ID переходов возвращают `false`, не открывая карточку. Закрытая комната может быть найдена как конфигурационная запись, но переход к ней через `navigate_to_habitat` и открытие деталей запрещены; этаж остаётся доступен для демо-обзора. Для увеличенного экрана вольера предусмотрены `open_room`/`show_room_info` и сигнал `habitat_inspect_requested`. Пользовательского перехода из бестиария или пустой кнопки будущей функции пока нет.

## Масштабирование

Экран создаёт секции только по текущему видимому диапазону. При смене диапазона сохраняет оставшиеся узлы и создаёт/удаляет только вошедшие/вышедшие секции. Весь комплекс не пересоздаётся каждый кадр. Невидимые фоны не обрабатываются; подсветка комнаты сама останавливается через 1,4 секунды. Полноценных анимаций поведения мутантов нет. Текстуры берутся из существующего каталога и кеша ресурсов Godot. Отделённые `complex_floor`/`habitat_view` позволяют позднее заменить временную графику и загрузить тяжёлые элементы по требованию.

`tests/fixtures/complex_50.json` содержит **50 этажей и 50 временных закрытых помещений**, высоты чередуются 200/240/280, полная глубина 11960 единиц. Он загружается только тестом через отдельный Registry; обычный вход всегда читает четыре демо-этажа. Проверены переходы по каждому из 50 этажей, список лифта до последней строки, границы, текущая секция, обработка невидимых декораций и мгновенные дальние переходы. Активны **не более четырёх секций** одновременно. Это структурная проверка масштабируемости, не замер FPS/памяти на Android.

## Ограничения

Это временная процедурная графика и демо-доступность. Нет строительства, кормления, исследований, развития камер, новых видов, валют, наград, пользовательского размещения комнат, миграции сохранений или постоянного прогресса комплекса. APK, физическое Android-устройство, аппаратный Back, TalkBack, поведение приложения в фоне и измерение производительности телефона не проверены. Для будущего экспорта нужны фильтры `data/complex/*.json` вместе с прежними JSON кампании/эксперимента. Человеческий плейтест комплекса ещё не проведён; положительная оценка PR №14 не является оценкой нового экрана.
