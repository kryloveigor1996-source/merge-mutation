# Ручной плейтест · PR №18

## Запуск

1. В GitHub Desktop выбрать `feature/modular-habitat-renovation`. Не отбрасывать существующие локальные изменения ради переключения.
2. Открыть `MergeMutation/project.godot` в Godot 4.7.2, дождаться импорта, F5.
3. Лаборатория → **КОМПЛЕКС** → этаж −1 → Рогач.
4. При первом запуске новой демонстрации ожидаются бетонная камера, простой пол, трубы, монитор, один Рогач и **0/10 · 0% · 3 очка**.
5. Если демонстрация уже сохранялась, появятся прежние предметы и остаток очков. Для чистого теста есть **ТЕСТ → СБРОС ДЕМО… → СБРОСИТЬ ДЕМО**.

Не добавлять `--habitat-stage-regression` или `--portrait-regression` для обычного плейтеста: эти внутренние аргументы оставлены только для старых автоматических проверок.

## Сохранения и меры перед тестом

Основной профиль v2 и демо-ремонт — разные файлы. Папку можно открыть через Godot Project → Open User Data Folder. Стандартный sidecar называется `merge_mutation_save_v2.json.habitat-demo-v1.json`.

При необходимости сделать копии обоих файлов перед экспериментами. Сброс в меню **ТЕСТ** меняет только демо-ремонт текущего вольера и создаёт резервную копию sidecar; он не сбрасывает монеты, коллекцию, кампанию и песочницу. «Новая игра» в общих настройках — другая, существующая команда.

Очки здесь исключительно тестовые. Их не нужно добывать в кампании, они не связаны с монетами и не будут автоматически перенесены в будущую экономику.

## Мобильные проверки

Повторить основные действия на 16:9, 18:9, 19.5:9, 20:9 и 16:10. Для физического Android отдельно проверить:

- Вырезы, системные панели, безопасные области.
- Читаемость подписей и удобство маркеров/кнопок пальцем.
- Приоритет панели выбора над миром.
- Системный Back во всех трёх вложенных состояниях.
- Сворачивание/возобновление и повторную загрузку прогресса.
- Производительность панорамы и прокрутки комплекса.

**В этой среде физический Android и эмулятор не тестировались.** Автоматические touch-события на Windows не считаются проверкой устройства.
