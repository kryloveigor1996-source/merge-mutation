# Mobile UI Design System — предложение для согласования

Статус: спецификация и отдельные макеты, не внедрённая система production-компонентов. Новая архитектура будет реализована после утверждения композиции по пункту4 ТЗ.

## Размерная модель

- Базовая ширина540 логических единиц; высота = полезная высота viewport / масштаб по полезной ширине. Не использовать `min(width/540,height/960)` для всего portrait-экрана.
- Safe-area приходит в координатах Android-окна; один раз преобразуется в координаты canvas. Внутренние контейнеры не должны вычитать её повторно.
- Пиксели, dp и логические единицы — три разные величины. Источник Android density/полезного dp viewport должен быть проверен на устройстве; `screen_get_dpi` сам по себе не гарантирует Android density bucket.
- Минимальная зона: `max(84,48*540/usable_width_dp)` по обеим осям. При360dp:84 ед.=56dp;320dp:49.8dp;288dp:84 ед.=44.8dp, поэтому нужен минимум90 ед. В таблицах галереи параметр условный, не измеренный Samsung.
- Для короткого/узкого экрана сначала свернуть вторичный текст в детали; затем уменьшать поле с сохранением квадратности, если без этого не помещаются безопасные минимальные цели. Не уменьшать touch-зоны ниже48dp ради фиксированного макета.

## Компоненты

| Компонент | Предлагаемый контракт |
|---|---|
| Shell |Full Rect anchors, SafeAreaContainer, VBoxContainer:Header/expand Content/Actions или Navigation. Общий единый маршрут Back.|
| Header |Back84×84, expanding title, Settings84×84; текст не вытесняет кнопки. Длинный заголовок переносится или сокращается с полным текстом в деталях.|
| Resources |Компактная строка прежних монет/биокапсул; никаких новых валют.|
| Card |PanelContainer + MarginContainer, контент через VBox/HBox/Grid. Вход в комнату по всей области; отдельная кнопка только если это другой смысл.|
| Button |Минимальная touch-зона через размерную модель, текст22–24 ед., перенос/минимум две строки для длинных локализаций. Отдельные disabled/focus/pressed.|
| Modal |Полностью непрозрачная подложка, один фокус/ввод, безопасная прокрутка текста; Back сначала закрывает.|
| Bottom sheet |Раскрытие по явной ручке/нажатию, preview без списания; покупка только подтверждением, отмена бесплатна. Порог свайпа не считается нажатием объекта.|
| Puzzle actions |Ходы + Undo/создание по наличию/вторичный restart. Новый undo не добавляется туда, где его не было.|
| Tooltip |В выделенном контекстном месте, а не поверх поля/главных кнопок. На коротком экране — краткое сообщение с раскрытием деталей.|
| Navigation |Три основных маршрута, стабильный низ; внутри головоломки/вольера заменяется соответствующей панелью действий, не дублируется.|

## Тема

Фон#11191D, панели#1D292E, разделители#35474E, основной текст#EFF5EE, вторичный#99AFB3, биология#A6D78B, порталы#B99ADD. На практике проверить контраст всех состояний и размытие/AA на телефоне. Массовый новый арт и окончательный Visual Identity не входят в этот этап.

Ритм:8/12/16/24 ед.; заголовки25–30, основной текст22–24, подписи18–20. Малые подписи не заменяют основную информацию. Увеличенный шрифт требует прокрутки/переноса, не пересечения прямоугольников.

Семантика действий PR22.1 сохраняется:угловые скобки выбора, → движение,+слияние,!способность,#механизм,◎портал, отдельная цена. Цвет не единственный носитель смысла.

## Адаптация и проверки после реализации

Portrait 360×640,360×720,360×800,412×915,540×960,540×1170,540×1200 и зеркальные landscape. Каждый размер испытывается отдельно с известной моделью density и inset, не автоматически объявляется dp по числу пикселей. Проверять safe-left/right, вырез, жестовую/кнопочную панель, большой текст и длину целей. Landscape — перестановка контейнеров в две колонки, не поворот/уменьшение всего portrait-холста.

Текущие макеты рендерятся отдельным CanvasItem с дизайнерскими координатами для быстрого согласования; это не замена требуемой контейнерной реализации. Параметры макетов в `portrait-review/regions.json`; независимые touch-прямоугольники не пересекаются.
