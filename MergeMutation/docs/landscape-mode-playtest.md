# Сравнительный плейтест ориентации · PR №17

## Запуск

1. Закрыть запущенную игру и редактор этого проекта. В GitHub Desktop убедиться, что нет несохранённых локальных изменений. Если они есть — сохранить их своим коммитом; не использовать Discard.
2. Выбрать существующую ветку `experiment/landscape-mode`, выполнить Fetch/Pull. Открыть `MergeMutation/project.godot` в Godot 4.7.2.
3. Дождаться импорта, нажать F5. Ожидается окно 960×540. Для обычного плейтеста не добавлять аргумент `--portrait-regression`.
4. «КОМПЛЕКС» → этаж −1 → Рогач открывает живую среду. «СТАДИИ · ТЕСТ» меняет временное оформление, «ПАНОРАМА» включает широкий мир, «НАЙТИ МУТАНТА» возвращает камеру к нему.

Из командной строки: `Godot --path "путь/к/MergeMutation"`.

## Безопасное сравнение с main

Вертикальная версия остаётся на main. Эксперимент не объединять до решения по плейтесту.

Перед сравнением сделать копию пользовательской папки сохранений через Godot: Project → Open User Data Folder. В ней находятся `merge_mutation_save_v2.json` и, если есть, старый legacy-файл. Не удалять их и не нажимать «Новая игра» ради смены ориентации. Оба варианта используют тот же формат v2; обычное прохождение в любой версии обновляет общий прогресс.

Для полностью независимого сравнения использовать две **тестовые копии** профиля либо отдельный каталог user data через возможности запуска Godot; не редактировать единственную копию реального сохранения. Автоматические тесты уже используют свои пути в `.godot/`.

1. Закрыть игру и редактор.
2. Проверить чистое дерево в GitHub Desktop и переключиться на `main` обычной командой интерфейса. Не выполнять reset/clean.
3. Открыть тот же project.godot, дождаться повторного импорта и запустить F5: ожидается 360×720.
4. Записать оценки тех же сценариев.
5. Снова закрыть игру/редактор и переключиться на `experiment/landscape-mode`, повторить импорт и F5.

Если Desktop сообщает о локальных изменениях или конфликте — остановить переключение и сохранить работу, а не отбрасывать её. Закрывать/открывать проект после каждого обычного изменения скрипта не требуется; при сравнении веток это помогает редактору корректно перечитать настройки ориентации.

## Оценка двух вариантов

Оценить каждую строку от 1 до 5 отдельно для main и эксперимента:

- Удобство управления головоломкой на телефоне.
- Читаемость целей и подсказок.
- Размеры и различимость помещений комплекса.
- Впечатление от четырёх стадий среды.
- Желание развивать комнату и отдельные предметы.
- Удобство панорамной камеры и поиска мутанта.
- Общая удобность одной рукой / двумя руками.

Записать предпочтительную ориентацию и три наиболее мешающих момента. Оценки предыдущего PR16 (средняя 3/5, размеры 3/5, различия стадий 2/5, желание развивать 2/5) служат отправной точкой; новые оценки ещё не собраны.
