## Причина внешней .godot

Подтверждение найдено в сохранённом `external-godot/editor/filesystem_cache10`:
его `res://` содержит AGENTS.md и корневые check/cleanup-логи. Правильный внутренний
индекс начинает `res://` с README.md и assets/. Следовательно, в прошлом Godot
индексировал **внешний корень репозитория как корень проекта**, а не вложенный проект.

Кроме движкового кеша туда складывались ручные тестовые артефакты и backup; поэтому
это не просто полностью восстанавливаемый кеш. Точная старая командная строка не сохранилась.
Неоднозначность одинаковых имён внешнего/внутреннего каталогов и относительные ручные
запуски объясняют накопление. Прежние PowerShell-обёртки уже передавали абсолютный --path,
но не закрепляли WorkingDirectory процесса; это теперь исправлено и проверено.

Новая общая функция всегда задаёт одновременно абсолютный --path, WorkingDirectory
внутреннего проекта и абсолютный --log-file внутри logs/. Перед/после каждого запуска
проверяется отсутствие внешней .godot; неожиданная папка вызывает ошибку, а не автоудаление.

Добавлены узкие исключения logs/** и builds/** с явными исключениями только шести .gitkeep,

Существующее отслеживание игровых файлов не менялось: gitignore не используется как
замена git rm --cached. Такое удаление здесь не выполнялось.

Из-за глубоких исторических shader-cache путей включён **только локальный**
`git config --local core.longpaths true`: обычный Git и аудит ignored-файлов
работают без предупреждений о длине путей. GitHub Desktop не переносился и не перенастраивался; его UI отдельно не автоматизировался. Глобальные настройки Git/Windows не менялись.

AGENTS уточняет границы проекта, внутренний Godot-корень, logs/builds/docs, запрет
корневых временных отчётов, правила ручного запуска и явный staged-контроль.
check_staged.ps1 дополнительно отклоняет принудительно добавленные generated/private файлы;
разрешает только штатные placeholders в logs/builds. Проверка остаётся ручной, не глобальным hook.

## Инструменты и будущие запуски

workspace_paths.ps1 определяет пути из расположения скрипта, не из текущего cwd.
check_gdscript.ps1 и check_landscape.ps1 сохраняют прежний состав проверок/флаги.
Каждый прогон получает отдельный UTC-каталог с датой, типом, меткой и коротким ID.
Это предотвращает перезапись предыдущих результатов.

run_godot.ps1 поддерживает import/runtime/script/export. Тестовые запуски изолируют
APPDATA и восстанавливают его после команды. Runtime — короткий smoke по умолчанию,
не замена пользовательскому запуску F5. Экспорт допускает только builds/android или
builds/windows, корректное расширение и новое имя; отсутствующие presets не создаются.

check_workspace.ps1 проверяет синтаксис PowerShell, независимость cwd, ignore/staged
контракты, отсутствие корневого кеша, запрет выходных путей вне logs/builds и сохранность
легитимных .png/.import/.uid/.json/.txt. Текущие команды приведены в [README](../README.md).
Старые отчёты сохранены как история этапов; их команды не являются текущей политикой вывода.
