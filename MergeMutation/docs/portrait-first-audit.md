# PR22.1: технический аудит portrait-first для PR23

Это предложения, не реализация редизайна. PR23 не начат. Сначала повторный Android-плейтест Mobile Control Fix.

## Подтверждённая обратная связь
Samsung Galaxy S26 Plus: пройдены 10/10 экспериментов; интерес, механики и подсказки 4/5; производительность 5/5; drag/tap 2/5; portrait 1/5, landscape 2/5. Предпочтения: portrait, два касания, сочетание классического Merge и тактики. Эти оценки относятся к PR22/versionCode22, не к новой APK23.

## Причины по исходному коду

| Участок | Сейчас | Последствие |
|---|---|---|
| evolution_geometry.gd / evolution_lab.gd | Единый дизайн 540×960 вписывается целиком с сохранением пропорций | На высоком телефоне 19.5:9 часть высоты остаётся вне дизайн-области; safe-area дополнительно уменьшает масштаб всего интерфейса |
| Заголовки/подвалы | Фиксированные Rect2 у каждого экрана, шапка комплекса 188px, навигация с y892 | Пространство распределяется по desktop-производной сетке, размер текста и зон touch зависит от общего масштаба |
| Игровое поле | 500×600, y208..808; действия начинаются на y828 | Поле уже занимает почти полную ширину, но цели, уведомления и подсказки конкурируют за одну верхнюю полосу; увеличение одной зоны ломает соседние |
| evolution_habitat.gd | Окно 516×620, мир 420px высотой масштабируется в 620/420≈1.476 раза | Видимая ширина мира 516/1.476≈349.5 против 940 в landscape. Это обрезка обзора камерой, а не неравномерная деформация рисунка; комнаты и предметы воспринимаются тесными |
| evolution_complex.gd | Комнаты перепроецируются с ширины 804 в 540, высоты этажей не меняются | Обзор превращается в узкие секции с ограниченным местом для подписей и обитателей |
| Навигация | Различающиеся абсолютные координаты и отдельные reflow для экранов | Одинаковые действия занимают разные места, устойчивость к длинному тексту и системному масштабу ограничена |

Проект использует `canvas_items` + `aspect=expand`, а адаптер затем снова вписывает целый фиксированный дизайн через `G.fit`. Например, при доступных 540×1170 дизайн540×960 оставляет 210 единиц высоты вне своего контента (около18%). Это расчёт для указанного соотношения сторон, не измерение физического Galaxy.

## Предложение для отдельного PR23

1. Ввести единый portrait shell: реальные safe-insets, компактная шапка, контент-контейнер, нижняя зона действий с минимальными touch-размерами. Учитывать высоту устройства, не вписывать один жёсткий холст целиком.
2. Игру проектировать от поля: квадратные клетки, фиксированная читаемая нижняя панель, краткие цели с разворачиваемой карточкой. Не перекрывать поле уведомлением. Развёрнутые описания вынести в необязательную панель.
3. Для вольера определить отдельную камеру обзора, а не подбирать масштаб по всей высоте окна. Предложить композиции: обзор комнаты сверху + карточка обитателя снизу или вертикальные зоны вольера. Существующие координаты мира, инсталляции и сохранения адаптировать через presentation-слой.
4. Комплекс строить как вертикальный обзор этажей с отдельными интерактивными карточками комнат; иллюстрации не сжимать вместе с текстом. Сохранить culling и скролл.
5. Оставить landscape вторичным адаптивным режимом, унифицировать расположение Back/Settings и семантику переходов.
6. Сначала согласовать два-три прототипа композиции на физических скриншотах, затем менять UI без изменения стоимости, наград, кампаний, музыки и сохранений.

## Приёмка следующего этапа (предложение)

Проверять 360×720, 360×800, 412×915, высокий экран Galaxy, вырезы/системные панели, длинные цели, крупный системный шрифт. Измерять физические touch-зоны и видимую долю мира, а не только попадание элементов в границы. Повторить реальный тест двумя касаниями, одной рукой, Back/сворачивание и обновление поверх предыдущего APK.
