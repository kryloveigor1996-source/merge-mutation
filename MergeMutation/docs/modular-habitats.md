# PR №18 · Modular Habitat Renovation

## Основа и границы

PR №17 объединён; база актуального main — `b83f25077e422169af1a9ade53dc47b6d7b420b1`. Рабочее дерево перед началом было чистым. Ветка — `feature/modular-habitat-renovation`. Основная ориентация теперь горизонтальная, 960×540; решение принято после ручного плейтеста PR17 (17/17, средняя сравнительная оценка 4,4/5).

Вольер `habitat_horn` получает постоянный **демонстрационный** ремонт. Рогач, его профиль, основной цикл поведения, ID этажей и помещений, прокрутка и панорама сохранены. Другие комнаты закрыты и не получают живых обитателей. Кампания, тактика, экономика, существа, игровые PNG и codec основного сохранения v2 не менялись.

## Данные и общий источник состояния

| Файл | Назначение |
|---|---|
| `data/renovation/catalog.json` | Индекс habitat_id → файл конфигурации |
| `data/renovation/horn.json` | Зоны, десять слотов, тридцать оформлений, геометрия, взаимодействия и зависимости |
| `scripts/renovation_catalog.gd` | Проверка конфигурации и проекция мировых координат |
| `scripts/renovation_state.gd` | Баланс, установленные оформления, транзакции, предпросмотр и отдельное сохранение |
| `scripts/modular_habitat_state.gd` | Адаптер целей взаимодействия к прежнему HabitatState |
| `scripts/renovation_art.gd` | Слоистая процедурная графика / точка замены на Texture2D |
| `scripts/modular_habitat.gd` | Наблюдение, ремонт, выбор дизайна и тестовое меню |
| `scripts/renovation_confirmation.gd` | Подтверждение сброса внутри общей safe area |

Статические данные отделены от динамических: JSON не содержит состояние игрока, а сохранение не копирует геометрию, имена, стоимость и текстуры. Количество слотов не зашито в модель или UI: списки и маркеры строятся по конфигурации; тест с одиннадцатым слотом проверяет расширение без копирования логики. Три варианта на слот и стоимость первой установки 1 являются требованиями текущего прототипа и проверяются валидатором.

В конфигурации есть стабильные `slot_id`, `habitat_id`, `zone_id`, `design_id`, имя/описание, `kind`, `rect`, `anchor`, `touch`, `collision`, `layer`, `requires`, `interaction`, `cost` и массив `designs`. `kind` выбирает визуальный адаптер, а не состояние конкретного слота. Например, второй слот спального места может иметь другой slot_id, сохраняя kind=bed. Индексы кнопок, порядок JSON и имена PNG не участвуют в сохранении.

Валидатор отклоняет повторы слотов, зон и design_id, отсутствующие варианты/текстуры, неверные habitat/zone/dependency-ссылки, циклы, неподдерживаемые взаимодействия/оформления, NaN, выход за мир, слишком маленькие области касания, пересекающиеся зоны и коллизии на дорожке. Каталог при ошибке очищается, частичная конфигурация не используется.

Ни одного отдельного симулятора для варианта мебели нет: обзор и деталь используют один ModularHabitatState, одну RenovationState и единственный HabitatActor в каждой среде отображения. Одновременно симулирует только видимая среда; обзор при открытой детали приостановлен. Обзор отображает те же установленные предметы и процент ремонта.

Оформления отличаются геометрией и деталями, а не только цветом. GPU-тест сравнивает изображение среды для всех трёх вариантов каждого слота, исключая заголовки панели выбора.

В будущих вариантах можно указать `texture: "res://assets/...png"`. Общий renderer кэширует Texture2D и вписывает его с сохранением пропорций в геометрию предмета; модели, ID, сохранения, коллизии и взаимодействия от смены изображения не зависят. Анимированные спрайты подключаются на этой же границе представления. Рекомендуемые исходники: обычный фон 1920×1080, панорама 3840×1080/сегменты, мутант около 256×256, предметы 128–512 px. Новые финальные ассеты в этом PR не создавались.

## Ремонт, цена и предпросмотр

Начальная комната имеет бетон, простой пол, трубы, базовый монитор и Рогача. Ни одного установленного слота; 3 демо-очка.

**РЕМОНТ** приостанавливает поведение и показывает маркеры. Нажатие открывает панель шириной 304 единицы на противоположной от предмета стороне. Панель не закрывает всю среду; выбор мгновенно показывает оформление в комнате. Предпросмотр хранит только временные ID, не списывает очки, не меняет фактические объекты/коллизии и не пишет файл. Отмена, Back или выход удаляют его.

Подтверждение первой установки стоит ровно 1 тестовое очко. Все три оформления имеют одну цену. Уже установленный слот меняется бесплатно, в том числе при нулевом балансе. Повторное подтверждение того же выбора — no-op без записи файла и без списания. При недостатке очков кнопка отключена, модель также независимо отвергает покупку. Прогресс — количество установленных известных слотов / общее число настроенных слотов: 0/10=0%, 3/10=30%, 10/10=100%. Процент ничего не переключает целиком в комнате.

**ТЕСТ** содержит «+1 тестовое очко», подтверждаемый сброс демо и информацию о вольере. К монетам, рекламе, кампании, тактическим наградам и будущей реальной валюте эти очки не привязаны.

В обычном UI глобальных стадий нет. Старая система оставлена только за внутренним аргументом запуска `--habitat-stage-regression` для прежних проверок поведения и интерфейса PR17.

## Поведение и коллизии

Сохранены прежние состояния idle, walk, sleep, inspect, react и ram. Общий адаптер выбирает цель по interaction слота: сон использует sleep, кормление/шкаф — inspect с короткой текстовой реакцией, игра — react и визуальное движение игрушки, тренировка — прежний ram. Не вводились голод, здоровье, наказания или отдельные FSM на дизайн.

Повторный запуск защищён текущей целью, intent, cooldown и состоянием действия. Касание самого Рогача сохраняет прежнюю реакцию. При пересечении зон установленный функциональный предмет имеет приоритет перед мутантом; ремонтные маркеры рассматриваются только в режиме ремонта. Некоторые установленные предметы выбираются автономно. После изменения установки недействующие цели отменяются; предпросмотр не перестраивает фактические цели.

Тренировка сохраняет цикл временной реакции и восстановления 4 секунды: валун/кристалл показывают обломки, механическая мишень наклоняется. После подхода справа Рогач разворачивается к предмету перед ударом. Предметы размещены в задней/передней полосе, свободная дорожка не перекрывается; отдельный collision_rect проверяется наземным драйвером. Проверены проходы в обеих проекциях и весь цикл действия.

## Панорама и мобильный ввод

Мир остаётся 2350×420, видимая область 940×440; обычная проекция имеет ширину 940. Запад — отдых, центр — тренировка/игры, восток — кормление/оборудование. Обе проекции используют один набор установленных design_id. Объекты не растягиваются пропорционально ширине мира, актёр сохраняет масштаб.

Сохранены drag мышью/первым touch, инерция, ограничение камеры 0…1410, поиск мутанта и накопленная длина жеста. Свайп туда-обратно и canceled touch не активируют предметы. UI имеет приоритет над средой. Back сначала закрывает подтверждение/выбор/тестовое меню, затем комнату. Камера помнит позиции обычного и панорамного вида в рамках открытого комплекса и восстанавливается при возврате в деталь. Полный выход и новое открытие комплекса начинают обычный вид; камера не является постоянным прогрессом.

Панель сброса — встроенный Control, поэтому следует той же safe-area трансформации, что и комната. Проверены пять форматов PR17 и минимальная высота её кнопок/кнопок выбора 44 логические единицы.

Renderer отсекает предметы за границами текущего участка. При перемещении камеры обновляются попадающие в видимость слои; статичные предметы не имеют собственных _process. Невидимые этажи и обзор под деталью не симулируют обитателя. Предел активных этажей сохраняется и в 50-этажной конфигурации.

## Сохранение демонстрации

Выбран отдельный sidecar: **полный путь основного профиля + `.habitat-demo-v1.json`**. Например, стандартный профиль использует `user://merge_mutation_save_v2.json.habitat-demo-v1.json`. Тесты используют отдельные пути в `.godot/`.

```json
{
  "format": "merge_mutation_demo_renovation",
  "version": 1,
  "habitats": {
    "habitat_horn": {
      "habitat_id": "habitat_horn",
      "points": 2,
      "installed": {"bed": "soft_bed"}
    }
  }
}
```

Это намеренно отдельное пространство демонстрационных данных, а не миграция основного профиля. В v2 не добавлены новые поля и нет автоматического импорта демо-очков в будущую реальную экономику. Формат допускает несколько habitat_id.

- Отсутствующий sidecar даёт пустую комнату с 3 очками, без записи при открытии.
- Файл обновляется только при подтверждённой установке/смене, явном тестовом начислении или подтверждённом сбросе.
- Запись идёт через временный файл и замену после flush. При ошибке записи баланс и установленные предметы не меняются.
- Перед записью читается свежий sidecar: изменения других вольеров сохраняются. Конфликтующее внешнее изменение текущей комнаты отвергается с предложением переоткрыть вольер.
- Неизвестные slot_id/design_id не отображаются и не входят в активный процент, но сохраняются в исходных данных при обычной записи. Неизвестные поля и другие вольеры также сохраняются.
- Повреждённый/будущий формат или неверный баланс блокирует изменения; исходник не заменяется автоматически.
- Подтверждённый сброс создаёт именованную по хешу резервную копию sidecar, сбрасывает только текущий демо-вольер к 3 очкам/0 предметам и сохраняет остальные известные комнаты. Для неизвестного будущего формата полный исходник остаётся в копии. Основной профиль никогда не сбрасывается этой командой.

Неподдерживаемые ID не превращаются в награды и не вызывают выдачу компенсирующих очков. Демо-файл можно отдельно архивировать при дальнейшем введении реальной экономики.
