## Согласованный перенос

Пользователь подтвердил **перенос всего репозитория после завершения PR19**:

| Откуда | Куда |
|---|---|
| `ChatGPT\Plus upgrade` | `ChatGPT\Games\Merge Mutation` |

Перенос выполняется последним локальным шагом после публикации PR и проверки закрытия
Godot/GitHub Desktop. Сохраняются `.git`, ignored-файлы, локальные журналы и вся рабочая
копия; существующая папка назначения не перезаписывается. Итог фактического переноса
сообщается пользователю отдельно после операции. Изменения истории Git не требуются.
Путь `Games\Merge Mutation` — корень репозитория; Godot-файл внутри него:
`MergeMutation\project.godot`.

Другие предложенные каталоги (`Games\Pixel Clicker Game`, `Work\APAC Portals`,
`Work\Competitor Benchmarking`, `Work\ENQ Automation`, `Work\IWG Presence Monitor`,
`Work\Reports`) остаются рекомендацией для соответствующих проектов. Пустые структуры
не создаются без необходимости; существующие документы не перемещались.

## Codex после переноса

Текущий локальный проект приложения привязан к старому пути. Переименование папки само
по себе не обновляет эту привязку; текущий чат также хранит исходный рабочий каталог.
Доступные инструменты не предоставляют изменения attached folders/primary root.

После переноса в приложении:

1. Меню проекта «Plus upgrade» → **Edit project**.
2. **Add folder** → выбрать
   `C:\Users\User\OneDrive\Documents\ChatGPT\Games\Merge Mutation`.
3. Навести на новую папку → **Make primary**. Убрать старую привязку `Plus upgrade`.
4. Для следующей разработки открыть чат из этого проекта и убедиться, что рабочий
   каталог указывает на новый корень. История текущего чата сохраняется.
5. Для несвязанных рабочих задач создавать отдельные local projects с собственными
   primary folders, не прикреплять их к проекту игры вторичными папками.

Это соответствует официальной инструкции [Projects and chats](https://learn.chatgpt.com/docs/projects#use-local-projects-for-folders-and-codebases).
Если менеджер Godot/GitHub Desktop запомнил старый путь, выбрать существующий новый
`project.godot` / Locate repository, а не клонировать вторую копию.

## Защита и её пределы

В корень добавлен `AGENTS.md`: только игра, проверка корня, игровые артефакты в проекте,
чужие документы вне него, явное добавление путей и просмотр полного staged-списка,
сохранность пользовательских файлов, подтверждение переносов и запрет auto-merge.
Полезных прежних инструкций в этом файле не было.

`tools/check_staged.ps1` проверяет staged-пути: разрешает игру и корневые Git/AGENTS-файлы,
отклоняет рабочие пути APAC/IWG/ENQ и офисные документы. Он вызван перед коммитом и
проверен положительным/отрицательным примером. Это **ручная проверка, не глобальный hook**.
Она классифицирует имена, а не смысл содержимого. Существующий `.gitignore` уже исключает
`.godot/`, журналы и временные файлы; широкие новые маски не добавлялись.

AGENTS и папки проектов не являются глобальной изоляцией или границей доступа к данным.
Они не меняют разрешения других чатов. Для надёжного разделения нужны отдельные рабочие
каталоги/проекты и внимательная настройка доступных источников каждого чата.
